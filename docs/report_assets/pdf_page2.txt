How to read the GUI
The live React screenshot (left) shows High Risk · 74.28%, the normalised importance bars, and
the signed force plot built from top_factors. Each row is a feature; the bar grows from the
centreline toward retention (green, left) or churn (red, right), and the printed number is the log-odds
contribution. This answers "why this customer?" rather than only "which features matter globally?".
Innovation · kNN marginalisation
A retention agent rarely has all 19 Telco fields. Instead of filling missing inputs with one made-up
"typical" row or per-column medians, the API averages the model over the 100 training customers
closest to the supplied inputs in tenure and monthly charges (distance in standard deviations).
Supplied values are applied to every one of those rows. This estimates P(churn | supplied)
by marginalising over the missing dimensions, so the score and its SHAP values stay on-manifold.
The response names the inferred fields in assumed_features and reports aggregation =
{method: neighbour_average, rows: 100}; a single-row fast path is used when every
input is supplied. SHAP values are averaged over the same look-alike rows, so the force plot
explains the number actually returned.
