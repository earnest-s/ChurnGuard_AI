DevOps — CI/CD, containers, orchestration & observability
The same repository ships a blocking lint/test gate, a multi-stage image, Kubernetes manifests with two replicas and Terraform for Azure.
Monitoring is built in, not bolted on.
CI gate · lint and tests before the image is built
.github/workflows/deploy.yml runs a blocking ci job on every push: install requirements-dev.txt, run flake8 (style errors fail the build), then
pytest (35 tests; the suite is hermetic). The deploy job has needs: ci, so it cannot start unless both pass.
Local mirror of the CI job (the public Actions screenshot is attached separately when the run completes).
Multi-stage Dockerfile
 FROM python:3.10-slim AS builder
RUN apt-get update && apt-get install \
    -y --no-install-recommends build-essential
RUN python -m venv /opt/venv \
 && /opt/venv/bin/pip install -r requirements.txt
FROM python:3.10-slim AS runtime
COPY --from=builder /opt/venv /opt/venv
COPY --chown=app:app . .
RUN useradd --uid 1001 --gid 1001 app
USER app
HEALTHCHECK CMD python -c "..."
CMD ["uvicorn", "main:app", "--port", "8000"]
Kubernetes (2 replicas)
 # k8s/deployment.yaml
spec:
  replicas: 2
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1001
      containers:
        - name: api
          readinessProbe:  /model-info
          livenessProbe:   /
Terraform (Azure RG + ACR)
 # terraform/main.tf
resource "azurerm_resource_group" "main" {
  name     = "${var.project}-rg"
  location = var.location
}
resource "azurerm_container_registry" "main" {
  name                = var.acr_name
  resource_group_name = azurerm_resource_group.main.name
  location            = azurerm_resource_group.main.location
  sku                 = "Basic"
  admin_enabled       = true
}
